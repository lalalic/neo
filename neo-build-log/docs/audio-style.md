# Neo Build Log Audio Identity

Neo Build Log should sound like a builder explaining what just happened at the
workbench: intelligent, direct, curious, and human. It is not a product trailer,
news voiceover, or corporate explainer.

## Narrator voice: Neo Builder

Primary production voice:

- language: Mandarin Chinese, with English technical names left natural;
- timbre: male, mid-low / mellow;
- delivery: conversational, close-mic, restrained confidence;
- pace: slightly faster than normal conversation, approximately `1.05–1.08x`;
- emotion: curiosity and satisfaction, not hype;
- emphasis: one important phrase per sentence at most;
- pauses: short pause after a problem statement or before a reveal;
- endings: fall naturally; do not use announcer-style upward energy;
- avoid: broadcast cadence, sales voice, exaggerated excitement, fake suspense,
  overly deep “movie trailer” delivery, or reading code identifiers unnaturally.

### Local TTS implementation

The production identity is the user's own voice. A verified reusable reference
already exists at `../vlog/runtime/voices/ray-talk.wav` (about 10.6 seconds,
16 kHz mono) with transcript in `../vlog/runtime/voices/stt-talk.txt`. Use this
as the default voice-clone reference; a future NeoX presenter take may replace
it only if it is deliberately accepted as a better reference.

`audio/tts-build-log.sh` also accepts explicit overrides:

- `NEO_BUILD_LOG_VOICE_REF=/path/to/reference.wav`
- `NEO_BUILD_LOG_VOICE_REF_TEXT='exact transcript of that reference'`

and then uses the cached Qwen3-TTS Base model for voice cloning.

If the Ray reference is unavailable, use the cached Qwen3-TTS CustomVoice model with
`Uncle_Fu` as the reproducible fallback:

- model: `mlx-community/Qwen3-TTS-12Hz-1.7B-CustomVoice-8bit`
- voice: `Uncle_Fu`
- language: `zh`
- speed: `1.06`
- adapter: `audio/tts-build-log.sh`

The adapter supplies the series delivery instruction. The synthetic fallback is emergency-only;
the Ray clone is the normal series voice. Keep the `Neo Builder` delivery
contract unchanged when switching identities so pacing and tone remain consistent.

### Markcut usage

From `neo-build-log/`, pass the adapter as Markcut's TTS CLI override:

```sh
npx @lalalic/markcut render runs/neo-build-log/<YYYY-MM-DD[-slug]>/episode.md \
  --tts './audio/tts-build-log.sh "{input}" "{output}"'
```

Set the two `NEO_BUILD_LOG_VOICE_REF*` variables before the command when the
accepted personal reference is available.

### Beat-level delivery

- **Hook:** concise, slightly quicker, no shouting. Sound like “here is the
  surprising problem I just hit.”
- **Problem / investigation:** neutral and observational. Let technical nouns be
  clear; do not perform them dramatically.
- **Discovery / build:** add a small lift in energy on the actual insight.
- **Evidence:** matter-of-fact. The screen is the proof; the voice should not
  oversell it.
- **Payoff:** slightly warmer and slower.
- **Next hook:** curious, unfinished, one sentence only.

## BGM: Neo Build Pulse

The recurring music bed is an original minimal electronic cue generated by
`audio/generate-theme.py`.

Identity:

- tempo: **96 BPM**, 4/4;
- tonal center: **A minor / open-fifth palette**;
- signature motif: **A → E → G**, used sparingly at the opening and payoff;
- texture: warm pad + muted machine pulse + soft low kick + very light digital
  ticks/noise;
- mood: focused, forward-moving, slightly curious;
- explicitly not: epic cinematic, EDM drop, lo-fi study beat, cheerful corporate
  ukulele, or dense synthwave.

The music should feel like machinery quietly running while the build happens.
It creates continuity between episodes without becoming the subject.

### Generate the BGM asset

From `neo-build-log/`:

```sh
./scripts/audio/build-theme.sh runs/neo-build-log/<YYYY-MM-DD[-slug]>/assets/bgm/neo-build-log-theme-v1.mp3
```

The generator is deterministic and uses no external samples. The wrapper uses
`uv --with numpy` and normalizes the MP3 to approximately `-16 LUFS` / `-2 dBTP`
before Markcut applies its much lower BGM mix volume.

### Mix contract

- master music asset is normalized as a normal music bed; Markcut controls the
  final narration relationship;
- default Markcut BGM volume: `0.14–0.18`;
- narration nodes should use `foreground:true` so the music ducks underneath;
- hook/opening can expose a little more of the motif before narration settles;
- during dense terminal/code explanation, music should be almost subliminal;
- payoff may let the music rise slightly after the final spoken phrase;
- never add continuous sound effects. UI clicks / impacts are only for an event
  that is meaningful in the story.

## Per-episode workflow

1. Use the same `Neo Builder` voice contract for all narration.
2. Generate/copy `neo-build-log-theme-v1.mp3` into the episode's local
   `assets/bgm/` directory so Markcut paths remain episode-relative.
3. Keep the motif and mix stable across episodes; vary only scene-specific SFX
   or an occasional secondary texture when the story earns it.
4. If presenter camera audio is used, prefer the real presenter audio for that
   beat instead of layering synthetic narration over the presenter.
5. Review voice intelligibility and music masking on phone speakers before final
   render approval.
