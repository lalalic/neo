# UI review checklist

Use this as a final gate. Mark each item pass, fail, or not applicable, with
one concrete observation or file/screen reference.

## Direction and hierarchy

- [ ] The selected mode, platform, user outcome, and three controls are explicit.
- [ ] The visual direction is grounded in the product subject, not a generic kit.
- [ ] Primary, secondary, and tertiary actions are distinguishable.
- [ ] Layout, type scale, contrast, surfaces, elevation, and spacing rhythm agree.
- [ ] The design has one memorable choice and no decoration without purpose.

## Interaction and states

- [ ] The main flow is understandable without hover or animation.
- [ ] Loading, empty, error, success, disabled, and recovery states are covered.
- [ ] Focus, keyboard order, touch targets, and touch alternatives to hover work.
- [ ] Motion explains change, can be interrupted, and respects reduced motion.
- [ ] AI/chat surfaces expose streaming, thinking, tool results, citations, and
      human recovery where relevant.

## Web and Chrome Extension

- [ ] Responsive/adaptive behavior and breakpoints are intentional.
- [ ] Popup/panel constraints, permission prompts, and durable-vs-ephemeral
      state are considered where relevant.
- [ ] Text, focus indicators, controls, and error messaging are accessible.

## iOS

- [ ] Safe areas, Dynamic Type, VoiceOver order/labels, and semantic contrast work.
- [ ] Native navigation, sheets/detents, dismiss gestures, context/swipe actions,
      SF Symbols, and haptics are used where they improve the task.
- [ ] Live Activity, Widget, reorder, or full-screen behavior is addressed when
      the product uses it.

## Handoff

- [ ] Every finding has evidence, impact, and a concrete next change.
- [ ] Specialist recommendations are reconciled into one prioritized plan.
- [ ] Unknowns and assumptions are called out; no external skill is presented as
      installed without verification.
