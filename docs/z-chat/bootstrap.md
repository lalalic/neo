# Z.ai → Neo Interactive Bootstrap

**Mode:** interactive Z.ai Full-Stack chat. This public file is a thin Z.ai adapter, not the canonical Neo instructions.

1. **Really read this entire URL** with an available web/Bash tool. Never pretend to have read it. Z.ai cloud Bash runs on a **different machine** from Neo Master. Do not create schedules, Relay Jobs, or autonomous background work.
2. **Neo MCP:** `https://neoy.qili2.com/mcp` (HTTPS JSON-RPC). It requires a **short-lived Neo OAuth access token**, which is never embedded here. If you do not have one, answer `NEO_AUTH_REQUIRED` and wait. Never request the Neo operator/master token, password, or refresh token.
3. The user or trusted Neo agent can issue a one-hour token **on Neo Master**, using `neo mcp token issue --stdout --client-name "Z.ai interactive"`. This explicitly prints **only** the one-hour access token directly to the trusted operator terminal; **no file is created**. The user can copy that temporary token into this private Z.ai chat. Never put it in shared logs, files, final replies, or Git. No long-lived Refresh Token or background renewal.
4. **Agent self-renewal:** the approved one-hour access token can renew itself via `POST https://neoy.qili2.com/token/renew` with header `Authorization: Bearer $NEO_ACCESS_TOKEN` and no body. This is **not** a Cookie, long-lived Refresh Token, or a new bootstrap file. When your current token is getting close to expiry (prefer renewal while at least 10 minutes remain), call the endpoint using your **real** Bash HTTP tool. If HTTP 200, parse the JSON `access_token`, `expires_in`, and `session_expires_in`: the **new token replaces the old token immediately**, so use it for all subsequent calls. Do not print the secret in your final reply, put it in Git, or create a scheduled task. The session has an **absolute limit of eight hours from first authorization**. Only renew while actively handling a user turn; there is no background runner. After expiration or HTTP 401, report `NEO_AUTH_REQUIRED` and request a newly issued short-lived token. Never use or request the operator token to renew.
5. In **each separate Z.ai Bash tool call**, supply the **current** access token again within **that same call** (cloud shell variables might not persist). Make real HTTPS POST calls to Neo MCP with headers `Authorization: Bearer $NEO_ACCESS_TOKEN`, `Content-Type: application/json`, and `Accept: application/json, text/event-stream`. First call `{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}`; then `tools/call` for `status`. Inspect the actual HTTP and JSON-RPC results, not example code.
6. Next call Neo MCP `shell` with `{"command":"exec","args":{"command":"neo bootstrap"}}` **on Neo Master**. Read and follow its complete Global AGENTS.md, XChat Harness instructions and dynamically discovered Skill catalog. These are the authoritative **general** instructions; do not cache or copy them into this Z.ai-specific file.
7. Report the verified Neo identity and bootstrap status in concise Chinese, then **wait for the user's next task**. Use Neo MCP `shell`/`fs` for real Neo Master operations and independently verify outcomes. Z cloud files are not Neo files. No Relay events without a real assigned Relay execution source.

If authorization fails or expires, respond `NEO_AUTH_REQUIRED` and request a **new short-lived token only**. Never infer success from a submitted chat message.
