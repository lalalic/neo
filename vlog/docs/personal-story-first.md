# Personal Story-first — 给生活加点料

**方向：给生活加点料。** 讲一个在加拿大生活的人主动尝试、走出去、观察、体验或发现了什么，让中国观众认识这个人和他遇到的生活。不是景点解说词，也不是每集重复口号或人生履历。媒体承载经历，风景不必逐幅讲解。

日常题材的观众期待、真实案例与编辑判断见 [Audience-first Vlog](audience-first-storycraft.md)。故事优先不等于写满旁白；观众愿意继续看这个人，比形容漂亮景色更重要。

## Director：先有完整故事，再考虑镜头

1. 读本集 source manifest、Visioner 的时间码/画面/真实语音、私人 `user.md` 与通过 `story-history.mjs search/inspect` 获取的真实故事；可按需查 `assets/personal-library` 中的已验收口述素材。**优先找能看见创作者在做什么、对什么产生反应的镜头**（出镜、抬头观察、主动转镜头、提出问题、面对岔路），再找故事角度；单纯的路面颜色、落叶、季节变化不能独自充当人物故事的主轴。若本人没有明确说出门目的，直接从眼前发生的事开场，别为了凑 `arc.everyday_goal` 编“本来只是想活动一下”。动机假设放在 `provenance.fictionalized`，不得写成经过确认的事实。
2. 先写一篇**读起来通顺的第一人称完整小故事** `personal-story.md`：起因/好奇 → 实际经历或探索 → 一个具体发现/结果/余味。**挫折、冲突、反转和前后对比均为可选**；有真实小插曲再写，没有就自然结束。不要为凑三幕硬编失败、任务、目标达成或励志总结。
3. 可以**调侃镜头里真正出现的事**，例如镜头歪了、风吹乱头发、手机总想拍、脚步突然停下等（具体例子必须有该 Run 证据）。允许轻微自嘲、生活化观察及适度想象的幽默比喻；笑点要自然，不把虚构事件/台词/心理活动讲成经过验证的事实，不嘲弄未经同意出镜的人。
4. 根据生活场景选择讲述密度：从一个具体瞬间吸引人 → 人物做了什么/遇见什么 → 自然落点。允许静音、环境声、停顿和视觉叙事；**不要尬讲风景**，也不要用“走出来 → 看了几处风景 → 今天有点小收获”来凑剧情。每句话须推进故事、揭示人物、提供有用语境或营造笑点；否则删去。事实不足就承认本集故事支点不足，不靠强行总结补救。
5. 先写自然口语的完整故事及 `personal-story.json`（`protagonist`、`arc`、`narrative`、`beats`、`provenance`）。`arc.everyday_goal` 是日常动机；`actions` 是实际发展；`outcome` 是具体发现/结果。`setback`/`contrast` 可省略。情节至少有 `setup`、`development`（或真实 `complication`/`response`）和 `payoff`，不强制冲突。`narrative` 与 Markdown 正文一致；每个 beat 有来源镜头 ID。
6. **按叙事节奏决定段落/旁白时长，再规划素材覆盖**。镜头挑选/复用/慢动作/照片运镜均只能来自可追溯原素材；避免为塞满视频而拖慢或反复画面。输出 `story.md`、`shot-selection.json` 和 `visual-brief.md`，保留每个 beat 的 `story_id`、`story_beat_id` 与真实 source ID，规划情节之间的自然画面与声音桥接。
7. 面向**主要生活在中国的中文观众**，把加拿大生活中不易理解但与本集相关的地域、季节、交通、生活习惯或地标用一两句口语化解释；不要假定观众知道安大略省、渥太华或当地道路名称，也不要硬塞百科。地点/文化/历史等外部知识需要可靠来源，不能凭 GPS 推断到访地标或发生过的事。可信 GPS 及解释性地图的具体条件见 [story/route/sound](story-first-route-sound.md)。
8. Director 交付前，**只把 `personal-story.json.narrative` 当成对中国观众讲的话，朗读一遍**：第一句是否具体而不套话？每句是否有新的动作、观察或人物反应？结尾是否由本集的真实细节自然得来，而非“给普通一天加点料”“也算有收获”等固定口号？把人名、地名、风景名词删去后还有没有一个人的具体动作/好奇/选择？如果答案只剩“路从黄线变成落叶”这类画面变化，那是风景编辑，不是故事；应回到真实人物镜头/声音重新选题，找不到就标记故事证据不足。不过关就重写，不靠满足 JSON schema 宣称故事完成。Editor 按情节完整性和听感节奏剪辑，Producer 不重新编故事。完整故事不等于每秒都要旁白。

## 从现有素材发现 Vlog 故事（而不是套故事模版）

借鉴 Vlog Recipe / Story Editor 的编辑原则：**先发现已拍下的故事，再决定镜头如何服务它**。这里是当前 Director 内部选题方法，不是新 Agent、新文件格式或独立剪辑引擎。

1. 在构思前用 Visioner 时间码、原声及人物行为找出 2–3 个**真实可拍到**的候选瞬间（不需要保存额外 JSON）：谁做了什么？镜头为什么转向？现场出现了什么小问题/反应？哪段能用原镜头兑现？优先本人出镜、对镜讲话、动作或关注对象，而不是“加拿大秋色很漂亮”。如果素材只有一个可信的人物瞬间，就只用一个，不硬凑三个。
2. **选择一条**观众会愿意跟着看的问题线，例如“他在看什么？”“这东西究竟是什么？”问题可小，未解答就自然留下好奇，不许假造结果、冲突、品尝或拍摄时的心理动机。以真实的有趣瞬间作可选冷开场，再用一句口语把观众带回现场。冷开场必须在本集真正出现，不等于标题党。
3. 每一段都要至少完成一件事：让观众看到人物行动/变化、知道一点必要背景、对前一小问题产生推进，或者留下**有用途的**现场声与停顿。删除不推进事件的漂亮风景；保留它们作为动作之间的短过渡而非另起主线。**信息决定镜头时长，不强迫每个 beat 用固定秒数。**
4. **对镜语言优先、旁白补缺**：已经核听的现场语音比新编的旁白更能呈现真实感。未核听的原声不丢掉：在 `story.md` / `visual-brief.md` 标上具体来源和时间段作为 **Editor 待核听的原声候选**，不把 ASR 当已验证台词，也不预先合成旁白覆盖掉它。画面本身已经在讲的动作和声音不用再念一遍；Editor 负责核听及 J/L 声音桥接。
5. 交付前做**真实口语删改**：把 `personal-story.json.narrative` 想象成发给国内熟人的一分钟语音消息。不要把观众当剪辑师解释“镜头/素材/拍摄计划”；也别用“今天又多了一点新鲜”“这趟没有什么大事”“也算有收获”等通用总结替代结尾。**最后一句尽量落在可指认的动作、现场声音、自然的问号或当时真实的话上；没有结语也可以直接停在画面/原声上。** 不要为了故事完整硬造答案；证据不够就短一点。

## 事实与创作边界

- `provenance.observed`：镜头/实听录音中可核对的事实，附 Visioner `source_id`。
- `provenance.inferred`：根据素材/时间/创作者画像作出的可能推断，写明依据，不能冒充确证。
- `provenance.fictionalized`：口语化的假设、主观表达或想象的笑话，单独标注；不能声称发生过未见证的人物对话、事件、路线或亲密家庭细节。
- **双层交付**：`personal-story.json.narrative` 和 `personal-story.md` 的故事正文必须是可直接朗读的观众文案；“录音转写里写着”“没核听”“素材证明”“这是创作假设”等事实/制作说明，只能写在 JSON `provenance` 或额外的非旁白说明里，不能进入故事正文。VTT 未核听时，不能把其中的“跑步”“骑车”“果子可以吃/尝起来酸甜”当成实锤；换成画面确实支持的行动或直接省略。
- 个人背景用于语气和理解动机，私密家庭信息及精确位置不自动公开；外部事实附可靠查询出处。
