# Producer human Preview event adapter

Relay owns the Task workflow and event contract. When the Producer is a managed Relay worker, call `neo.markcut_preview` for the current `video.md` with `review: {delivery: "event", eventTemplate}`. Build the template from the **canonical injected Relay Event Contract**: `type: "task.interactive_decision"`, copy the exact authorized `source` string from Task context, and set only immutable `data.interactive.jobId`, `taskId`, `executionId`, and stable `invocationId` (unique per review request). These values must match the current execution. Do not invent or prefill `decision`, `feedback`, `comments`, `revision`, `revisionId`, `contentHash`, `previewId`, `requestId`, or `idempotencyKey`: the Preview UI fills them after a human submits feedback, then publishes through the authenticated Events MCP. Do not publish `markcut.review.submitted` for a Relay-controlled review and never substitute Final Reviewer `review.approved`, `review.changes_required`, or terminal `task.completed`.

Stand-alone interactive ChatGPT Preview continues to use default `text` delivery through `ui/message`. In Relay mode, do not silently fall back to text on Event transport failure. Human approval binds the exact reviewed content hash. Relay accepts the event and records its decision, but **transport receipt alone does not mean the Producer was resumed**: the active Worker must consume its accepted decision or the authorized Relay continuation/recovery path must bring the original Task back. Do not claim review passed, render approved, or Task complete without current-version human approval and real playable/audible output. Repeated review requests must use new invocation IDs; retrying the same submission preserves its idempotency key.
