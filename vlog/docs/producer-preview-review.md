# Producer human Preview event adapter

Relay owns the Task workflow and event contract. When the Producer is a managed Relay worker, build the Event Template from the **canonical injected Relay Event Contract**: `type: "task.interactive_decision"`, copy the exact authorized `source` from Task context, and set only immutable `data.interactive.jobId`, `taskId`, `executionId`, and a stable `invocationId` unique per review request. Those fields must match the current execution. Never prefill `decision`, `feedback`, `comments`, `revision`, `revisionId`, `contentHash`, `previewId`, `requestId`, or `idempotencyKey`: the Preview UI fills them after the human submits feedback, then publishes through authenticated Events MCP. Never emit a Markcut-specific event, a Final Reviewer verdict, or terminal `task.completed` from Preview.

**Codex / terminal Producer on Neo Master:** Write the immutable template to a JSON file, then run `markcut preview <absolute-video.md> --delivery event --event-template <absolute-template.json>`. This uses the Markcut hosted-preview compiler (not the ordinary local browser), discovers the `neox` phone MCP over Bonjour or uses `--phone-url` / `NEOX_MCP_URL`, then delivers `review.request` to the iPhone. The CLI output `status: "review_requested"` means **the mobile inbox accepted the request only**. The phone must be reachable with Neo running; a failed request does not silently switch to Text. Review comments/decisions return asynchronously via Event Bus to Relay. The CLI does not await the human and does not itself resume a Codex thread. New video revisions need new invocation IDs; use the same `--request-id` UUID only when retrying an uncertain ACK for the same revision.

**ChatGPT-hosted Producer:** Call `neo.markcut_preview` for current `video.md` with `review: {delivery: "event", eventTemplate}`. Its hosted Preview UI publishes the same `task.interactive_decision` contract; do not treat the tool's compilation receipt as an approval.

Stand-alone interactive ChatGPT Preview continues to use default `text` delivery through `ui/message`. In Relay mode, do not silently fall back to text on Event transport failure. Human approval binds the exact reviewed content hash. Relay accepts the event and records its decision, but **transport receipt alone does not mean the Producer was resumed**: the active Worker must consume its accepted decision or the authorized Relay continuation/recovery path must bring the original Task back. Do not claim review passed, render approved, or Task complete without current-version human approval and real playable/audible output. Repeated review requests must use new invocation IDs; retrying the same submission preserves its idempotency key.
