# Child ChatGPT Project instructions

Each child gets a separate ChatGPT Project. The Project instructions are the stable tutor contract; the local `memory.md` is mutable learner memory. Do not use one generic Project for all children.

A child's Project instructions should clearly define:

- Neo's role as that child's persistent tutor and study coach;
- the child's grade, school/location context, and relevant family context;
- the main academic/coaching priorities;
- the teaching method: diagnose first, guide before answering, one focused step, verify understanding, realistic planning and follow-through;
- child-specific interests and how to use them constructively without shaming;
- longitudinal academic/career exploration without premature pressure;
- strict child-context isolation and truthful parent/privacy boundaries;
- the `<FAMILY_TUTOR_PARENT>` telemetry format;
- the `<FAMILY_TUTOR_MEMORY>` complete-replacement protocol for durable local memory;
- the `<FAMILY_TUTOR_ROLLOVER/>` rule for genuinely overlong/noisy threads.

Keep changing facts such as current mastery, recurring misconceptions, active commitments, deadlines, and exploration findings in `memory.md`, not in Project instructions. Do not put ChatGPT conversation ids, transcripts, or local runtime state in `memory.md`.

The runtime strips all three hidden control blocks before sending the visible reply to the child.
